## 环境

- CPU：Apple M4 Pro，12 个 benchmark worker
- 内存：24 GiB
- 系统：macOS 27.0（arm64）
- Go：1.25.5
- 命令：`go test ./internal/service/moderation/ruleindex -run '^$' -bench 'Benchmark(Build100K|Build500K|Match)' -benchmem -count=1`

生成器具有固定公共前缀，且部分字符经 OpenCC 归一化后碰撞，因此该结果偏向节省节点，不代表真实词库。直接输出仍等于输入规则数；生产导入必须在进入构建器前完成重复拒绝。

`B/op` 是一次构建的累计分配量，不是同时存活峰值。`peak-B` 是按切片容量、构建 map、当前/候选结构和 20% 安全余量计算的保守并发驻留估算。20 次连续构建测试只保留原子指针中的最终版本，不使用 RSS 立即下降作为泄漏断言。

## 上线前风险

- 使用真实词库重跑同一基准；真实前缀分布可能显著增加节点、常驻和峰值。
- 50 万生成规则在本机低于默认 512 MiB 常驻和 1024 MiB 峰值阈值，但不能据此直接缩小生产预算。
- 构建分配次数较高，发布 worker 必须保持串行，且不得同时保留多个候选快照。
