# 文章编辑资源处理设计

## 背景

文章正文以 Markdown 存储。正文中的本站图片不应以 CDN URL 入库，而应保存稳定对象 key，例如 `articles/{id}/images/{md5}.png`。接口返回文章详情时，再把对象 key 转成 Garage/CDN 可访问 URL，供详情页和编辑页直接渲染。

本设计覆盖文章新建、编辑、正文图片临时上传、保存时资源归档、旧资源清理和 CDN URL 反解。

## 目标

- 新建/编辑文章时，前端可以上传并插入可渲染图片。
- 数据库只保存本站对象 key，不保存签名 CDN URL。
- 保存文章时，将临时图片复制到文章正式目录。
- 编辑文章时，将旧正文中已不再引用的正式图片迁移到 `deleted/` 前缀。
- 完全禁止外链图片，发现后返回明确业务错误。
- 资源处理失败时避免数据库指向不存在的对象。

## 临时上传接口

新增登录用户可调用的临时图片上传接口：

```text
POST /uploads/temp
```

请求使用 `multipart/form-data`：

- `file`：单张图片。
- `dir`：临时子目录，只允许 `images`、`covers`。

对象 key 由后端生成，前端不能指定完整路径：

```text
temp/articles/{userID}/{dir}/{md5}.{ext}
```

响应返回对象 key 和可访问 URL：

```json
{
  "key": "temp/articles/7/images/d018d0f4f7b2050d9399e96f87a97b83.png",
  "url": "https://cdn.example.com/blog/temp/articles/7/images/d018d0f4f7b2050d9399e96f87a97b83.png?a=..."
}
```

接口限制：

- 仅已登录用户可调用。
- 普通注册用户使用严格限流。
- admin 频率放宽，但仍必须限流。
- 单文件上限 10MB。
- 图片格式与碎语图片一致：JPG、PNG、WebP、GIF。
- 必须做真实内容校验，不能只信任扩展名或 `Content-Type`。
- 可按内容 MD5 去重；同 key 已存在时直接返回 URL。

## 保存文章流程

保存接口仍由管理端文章保存入口承载。前端提交 Markdown 时，正文中可能包含已返回的本站 CDN URL，后端保存前必须统一规范化为对象 key。

### 新建文章

新建文章采用简洁版流程：

1. 在 DB 事务中先插入文章基础记录，拿到文章 ID。
2. 解析 Markdown，识别本站临时图片 URL/key。
3. 将临时对象复制到正式路径：
   `articles/{articleID}/images/{md5}.{ext}`。
4. 确认所有正式目标对象存在。
5. 将 Markdown 中的本站图片统一改写为正式 key。
6. 更新文章正文、分类、标签、音乐、推荐关系并提交事务。
7. 事务成功后删除对应 `temp/articles/{userID}/...` 临时对象。

如果复制或校验失败，事务回滚，已复制到正式路径的对象需要删除，临时对象保留，前端可重试。

### 编辑文章

编辑文章使用先复制、后提交、最后清理：

1. 读取旧文章正文和封面 key。
2. 解析新 Markdown，反解本站 URL 为对象 key。
3. 复制新引用的临时对象到正式路径，先不删除临时对象。
4. 确认所有正式目标对象存在。
5. DB 保存新正文和关联关系。
6. DB 成功后删除已归档的临时对象。
7. DB 成功后计算旧正文与新正文差集，将旧文不再引用的 `articles/{id}/images/...` 迁移到：
   `deleted/articles/{id}/images/...`。

如果 DB 保存失败，删除本次复制出的新正式对象，临时对象保留，旧正式对象不动。

## CDN URL 反解规则

反解逻辑必须封装为统一工具，供文章保存、文章删除、历史迁移等场景复用。

输入可以是：

- 已签名 CDN URL。
- Garage/S3 endpoint URL。
- 已经是对象 key 的字符串。

规则：

1. 仅接受本站 CDN host 和 Garage/S3 endpoint 白名单。
2. 绝对 URL 只取 `Path`，丢弃 query 和 hash。
3. 如果 path 形如 `/{bucket}/{object}`，剥掉 bucket。
4. 对 key 做归一化：
   - 去前导 `/`；
   - 使用 `path.Clean`；
   - 禁止 `..`；
   - 禁止空 key。
5. 文章保存只允许以下前缀：
   - `temp/articles/{userID}/images/`
   - `temp/articles/{userID}/covers/`
   - `articles/{articleID}/images/`
   - `articles/{articleID}/cover/`
6. 凡是 Markdown 图片中出现非本站 URL，直接返回业务错误，例如：
   `文章图片不支持外链，请先上传到本站：{url}`。
7. 非图片普通链接不参与资源归档；如果它是外部链接，允许保留。

Markdown 图片识别至少覆盖：

- `![alt](url)`
- `<img src="url">`

如后续编辑器会生成更多图片语法，再扩展解析器测试用例。

## 资源一致性策略

DB 与 Garage 无法共享事务，因此采用“先复制、后提交、最后清理”的补偿模型：

- DB 不会指向未复制成功的正式对象。
- DB 失败时删除本次复制出的正式对象。
- 临时对象只有在 DB 成功后才删除。
- 旧正式对象只有在 DB 成功后才迁移到 `deleted/`。
- 清理失败不应回滚 DB，但应返回错误并记录日志；重复清理必须幂等。

该策略的残留风险是：DB 成功后，临时删除或旧资源迁移失败，会留下垃圾对象或未迁移对象；但不会造成文章图片坏链。后续可通过后台清理任务补偿。

## 前端约定

- 编辑器插入图片时，先调用临时上传接口。
- 前端将响应中的 `url` 插入 Markdown。
- 保存文章时直接提交当前 Markdown，不需要额外传图片列表。
- 后端响应文章详情时继续返回可渲染 CDN URL。
- 保存成功后，前端用后端返回的文章详情刷新编辑器状态，避免继续持有临时 URL。

## API Risk Pass

- 谁能调：临时上传接口要求登录；文章保存仍为 admin。
- 输入边界：`dir` 白名单，单文件 10MB，图片格式真实校验，Markdown 外链图片拒绝。
- 资源成本：上传和保存都会访问 Garage；上传接口按用户限流，admin 放宽但不免限流。
- 失败收口：采用复制后提交和失败补偿；避免 DB 指向不存在对象。
- 旧状态清理：编辑保存成功后迁移不再引用的旧正式图片。

## 测试

- 临时上传：未登录、限流、非法 `dir`、超大小、非法图片、成功上传、重复上传。
- URL 反解：CDN URL、Garage URL、bucket 前缀、query/hash、路径穿越、外链拒绝。
- 新建文章：临时图片归档、DB 失败清理正式副本、成功后删除临时对象。
- 编辑文章：保留仍引用旧图、迁移删除旧图、归档新临时图、外链图片返回具体错误。
- 文章详情：正式 key 继续解析为 CDN URL。
