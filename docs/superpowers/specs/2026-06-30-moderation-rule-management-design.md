# 审核规则管理与大规模词库设计

## 1. 目标与范围

为现有内容审核系统补齐后端规则管理 API、批量导入流水线和管理端页面。系统面向单机单实例部署，日常预计维护约 10 万条有效关键词，容量上限按 50 万条设计。

本期实现：

- 管理员查询、筛选、新增、修改、启用和停用规则。
- 批量启用或停用规则，单次最多 1000 条。
- 按分类、风险、类型、来源和状态管理规则。
- 使用当前或候选规则集执行文本试跑。
- CSV 与 UTF-8 TXT 流式导入、预检、错误报告、确认发布和任务历史。
- CSV/TXT 导入模板下载与当前规则流式导出。
- 基于紧凑 Aho–Corasick 索引的大规模关键词匹配。
- 规则集版本追溯、候选构建、内存阈值保护和单实例热切换。
- 管理端桌面表格、移动端卡片、导入进度和候选版本试跑。

本期不实现：

- 内置或自动下载第三方敏感词库。
- 多实例版本广播、Redis 同步或实例就绪协调。
- 多人审批、草稿协作和规则集回滚。
- AI 语义审核、谐音模型、图片识别或外部付费审核服务。
- 导入时覆盖现有规则；导入只增加新规则，重复项必须先处理。

公开词库的授权、准确性和时效性由管理员确认。规则数量不等于合规能力，关键词层只负责明确的文本信号，语境不确定内容继续进入人工审核。

## 2. 关键约束

- 生产数据层继续使用 MySQL，运行时匹配在 Go 进程内完成。
- 普通审核请求不得逐条查询规则或线性遍历全部关键词。
- 规则内容不可原地覆盖；修改生成新规则 ID，历史审核记录仍能读取旧内容。
- 每条审核版本继续保存实际使用的 `ruleset_version` 和 `rule_match_ids`。
- 任意导入行失败时整批不可发布；数据库不得出现部分导入。
- 新索引构建期间旧索引继续服务；候选失败不得影响当前规则集。
- 所有管理接口仅注册在现有管理员路由组，响应使用 `dto.*`，不得返回 `model.*`。
- 日志只记录任务、版本、规则 ID、统计和错误类型，不记录完整敏感词内容。

## 3. 方案选择

采用“MySQL 规则事实源 + 单实例 Go 内存索引”。MySQL 保存规则、版本、变更和导入任务；后台构建候选索引文件；发布时在当前进程内短暂设置分类写屏障并原子替换不可变快照。

不采用独立审核服务，因为当前只有一个博客后端实例，独立服务会增加网络超时、熔断和部署成本。不采用数据库实时匹配，因为 10 万至 50 万规则下无法满足审核写请求的延迟和稳定性要求。

## 4. 规则语义

### 4.1 规则类型

- `keyword`：普通关键词，进入 Aho–Corasick 索引。
- `regexp`：Go RE2 正则，数量受独立上限约束。
- `composite`：由至少两个 `&&` 信号组成，沿用现有组合规则语义。

关键词、正则和组合规则均保存：名称、分类、风险等级、优先级、来源和规则效果。

### 4.2 风险与效果

- 风险等级保持 `low`、`medium`、`high`。
- 规则效果分为 `review` 和 `allow`。
- `review` 规则参与风险计算，所有命中取最高风险。
- `allow` 仅支持关键词，用于抑制其覆盖范围内的 `review` 关键词命中，不能绕过正则、组合规则或独立于该范围的其他命中。
- 高风险规则只应承载高置信信号；语境不明确规则使用中风险并进入人工审核。

### 4.3 分类与来源

首期分类使用受控值：`politics`、`pornography`、`violence`、`terrorism`、`gambling`、`drugs`、`fraud`、`abuse`、`advertising`、`minors`、`other`。DTO 同时返回稳定键和中文显示名，前端不自行翻译后端未知值。

`source` 是最长 100 字符的管理员标签，用于区分手工维护、采购词库或特定导入批次，不用于授权判断。

### 4.4 归一化与重复

关键词使用与分类器相同的 Unicode、繁简、全半角、大小写、零宽字符和异常分隔符归一化。活动规则的重复键由 `effect + rule_type + normalized_pattern` 计算。

- 文件内部出现相同重复键：对应行报错。
- 与当前活动规则重复：返回已有规则 ID 并报错。
- 任意重复都使整批导入不可发布。
- 正则和组合规则按规范化前的精确模式计算重复键，避免改变表达式语义。

## 5. 数据模型与历史追溯

### 5.1 `moderation_rule`

在现有表基础上扩展：

- `category`、`effect`、`source`
- `normalized_pattern`、`dedupe_hash`
- `activated_version`、`deactivated_version`
- `root_rule_id`、`replaces_rule_id`
- `created_by`

名称、类型、模式、分类、效果、风险和优先级创建后不修改。`deactivated_version` 和当前 `enabled` 投影允许在发布事务中更新；它们描述生命周期，不改变历史规则内容。

修改规则时创建新 ID，新记录通过 `root_rule_id` 和 `replaces_rule_id` 连接旧记录。停用设置旧记录的停用版本；重新启用时创建内容相同的新记录，避免重写旧规则的有效区间。

规则属于版本 `V` 的条件为：

```text
activated_version <= V
AND (deactivated_version IS NULL OR deactivated_version > V)
```

因此无需为每个版本复制几十万条成员关系，也能还原任意已发布版本。历史审核项保存的规则 ID 永远指向当时实际命中的不可变规则内容。

### 5.2 `moderation_ruleset`

每个候选或已发布版本一行：

- 单调递增 `version`
- `status`：`building`、`ready`、`publishing`、`published`、`failed`、`superseded`
- 基于的已发布版本 `base_version`
- 关键词、正则、组合和白名单数量
- 节点数、边数、索引预计内存、构建峰值估算和构建耗时
- 索引对象键、二进制格式版本和 SHA-256 校验和
- 操作者、失败类型和时间字段

任一时刻只有一个 `published` 版本作为当前事实源。失败版本允许造成版本号空洞，版本号不复用。

### 5.3 候选变更

`moderation_rule_change` 保存新增、修改和批量状态操作的候选变更。失败候选不直接改活动规则的有效区间。只有候选索引构建成功并进入发布事务后，才批量插入新规则或设置旧规则的停用版本。

### 5.4 导入任务

`moderation_rule_import` 保存：

- 文件名、格式、大小、对象键、来源和默认字段
- 状态：`queued`、`validating`、`building`、`ready`、`publishing`、`published`、`failed`、`canceled`
- 总行数、有效数、重复数、错误数和候选规则集版本
- 错误报告对象键、构建统计、操作者和时间字段

`moderation_rule_import_item` 暂存已解析行、行号和校验结果。原始文件、错误报告和暂存行默认保留 7 天；任务摘要默认保留 30 天，保留期可配置。清理由 moderation worker 完成，不引入通用批处理平台。

## 6. 运行时匹配索引

### 6.1 紧凑 Aho–Corasick

关键词使用按 rune 构建、以连续数组保存的 Aho–Corasick 自动机。节点、边、失败指针和输出区使用扁平切片，不为每个节点分配 `map[rune]`。运行时快照完全不可变，通过原子指针读取。

一次分类流程：

1. 按现有规则清洗并归一化输入。
2. 使用 allow 自动机定位白名单范围。
3. 使用 review 自动机一次扫描关键词命中。
4. 丢弃完全包含在 allow 范围内的关键词命中。
5. 执行有上限的 RE2 与组合规则。
6. 去重规则 ID 并取最高风险。

复杂度主要取决于输入长度和实际命中数，不随关键词数量线性增长。

### 6.2 索引文件

候选构建成功后写入版本化二进制索引文件，并保存到现有对象存储的 `moderation/rulesets/` 前缀。文件包含格式版本、规则集版本、各数组长度和校验和，不包含 Go 指针。

发布时重新读取并校验候选文件。启动时优先加载当前版本索引文件；文件缺失、格式升级或校验失败时从 MySQL 重建。`enforce` 模式下索引既无法加载也无法重建时拒绝启动。

### 6.3 单实例热切换

候选索引在分类写屏障之外构建。发布时：

1. 读取候选文件并完成校验。
2. 获取规则发布互斥锁和分类写屏障。
3. 在 MySQL 事务内应用候选变更并更新当前规则集。
4. 提交成功后原子替换内存快照。
5. 释放写屏障，旧快照等待现有读取完成后回收。

分类请求只在步骤 3 和 4 的短窗口暂停，不等待索引构建。数据库提交失败时不替换快照。系统不实现 Redis 发布通知、数据库版本轮询或多实例就绪状态。

## 7. 容量与配置

新增配置：

```yaml
moderation:
  rules:
    max_pattern_chars: 500
    max_keyword_rules: 500000
    max_enabled_regex_rules: 500
    max_import_rows: 200000
    max_import_file_mb: 50
    max_index_memory_mb: 512
    max_build_peak_memory_mb: 1024
    index_build_timeout: 10m
    import_artifact_retention_days: 7
    import_history_retention_days: 30
```

所有配置支持 `BLOG_` 环境变量覆盖并在启动时校验为正数。`max_build_peak_memory_mb` 必须大于 `max_index_memory_mb`。

构建器按切片容量、节点、边、输出、规则元数据和当前快照大小进行保守记账：

- 候选常驻估算超过 `max_index_memory_mb`：终止构建。
- 旧索引、候选索引和构建临时结构的峰值估算超过 `max_build_peak_memory_mb`：终止构建。
- 终止只标记候选失败，当前快照不变。

目标容量的规划值：10 万关键词常驻约 40–120 MB、构建峰值约 120–300 MB；50 万关键词常驻约 200–500 MB、构建峰值约 600 MB–1.2 GB。最终以真实词库基准结果为准。

## 8. 后台任务与导入流程

单进程 moderation worker 串行处理规则索引构建，避免两个大型构建同时占用内存。任务状态持久化，进程重启后将中断的 `validating` 或 `building` 任务恢复为 `queued`。

导入流程：

1. 管理员上传 CSV 或 UTF-8 TXT；handler 流式限制请求体并保存临时对象。
2. Worker 流式读取，验证 UTF-8、字段、行数、模式长度、类型、分类、风险和优先级。
3. 分批写入暂存表，检查文件内重复及当前活动规则重复。
4. 生成完整逐行错误 CSV；任意错误使任务进入 `failed`，不得发布。
5. 无错误时创建候选版本，合并当前活动规则和暂存新增规则。
6. 构建候选索引，检查规则数和两个内存阈值，保存索引文件与统计。
7. 任务进入 `ready`；管理员可查看统计、下载错误报告或使用候选版本试跑。
8. 管理员确认后执行单实例热切换，任务进入 `published`。

导入是 add-only。CSV 内 `pattern` 必填，其他字段可由行值或上传表单默认值提供；行值优先。`name` 为空时使用“来源 + 行号”生成，不把模式内容复制进名称。TXT 每个非空、非注释行是一条关键词，统一使用上传表单的分类、风险、效果、优先级和来源。

## 9. 管理 API

全部接口挂载在 `/admin/moderation`，沿用管理员 JWT、统一响应和 normal 写限流。

### 9.1 规则

- `GET /rules`：按关键词、分类、类型、风险、效果、状态和来源服务端分页；`page_size` 最大 100。
- `POST /rules`：新增规则，带 `expected_ruleset_version`，自动创建、构建并发布候选。
- `PATCH /rules/:id`：创建替代规则，带 `expected_ruleset_version`，不覆盖旧内容。
- `POST /rules/batch-status`：最多 1000 个 ID，批量启用或停用并发布一个候选版本。
- `POST /rules/test`：最多 10000 字符，可选择当前版本或一个 `ready` 候选版本，返回命中规则 DTO 和最终风险。
- `GET /rules/export`：流式导出当前筛选结果的 UTF-8 BOM CSV，并防止电子表格公式注入。
- `GET /rules/status`：返回当前版本、候选任务、规则数量、索引统计和配置上限。

新增、修改和批量状态操作返回发布任务。前端显示构建状态，当前规则集在任务成功前保持不变。`expected_ruleset_version` 过期返回 `409 MODERATION_RULESET_CONFLICT`。

### 9.2 导入

- `GET /rule-imports/template?format=csv|txt`：下载带字段说明的模板。
- `POST /rule-imports`：multipart 上传并创建任务。
- `GET /rule-imports`：分页查询任务历史。
- `GET /rule-imports/:id`：查询任务进度、统计和候选版本。
- `GET /rule-imports/:id/errors`：流式下载逐行错误报告。
- `POST /rule-imports/:id/publish`：发布 `ready` 候选，带 `expected_ruleset_version`。
- `DELETE /rule-imports/:id`：取消尚未发布的任务。

模板不得包含会被误发布的真实敏感词。CSV 模板使用以 `#` 开头的说明行、标准表头和一条明确停用的示例，导入器只允许在表头前跳过 `#` 说明行；TXT 模板仅包含以 `#` 开头的说明行。

## 10. 管理端设计

在 `../blog-frontend/apps/admin` 现有“内容审核”页面新增“规则管理”标签页，不新增独立导航入口。

### 10.1 页面结构

- 状态区：当前规则集版本、关键词/正则/组合数量、索引预计内存、最近发布时间和候选状态。
- 工具栏：新增规则、文本试跑、批量导入、下载模板、导出规则。
- 筛选：搜索、分类、类型、风险、效果、启用状态和来源，并同步 URL 查询参数。
- 桌面端：服务端分页表格和多选批量操作。
- 移动端：卡片列表，保留完整字段和行操作，不裁剪为不可操作的横向表格。
- 行操作：查看、修改、启用或停用。

新增和修改使用表单弹窗。提交后展示候选构建进度；成功后刷新状态和列表，冲突时提示刷新而不覆盖用户输入。

### 10.2 文本试跑

试跑弹窗允许选择当前版本或 `ready` 候选版本，输入测试文本后展示：最终风险、规则集版本、命中规则、分类、命中片段和是否被 allow 规则抑制。接口与 UI 只对管理员开放。

### 10.3 导入弹窗

分步流程：

1. 下载 CSV/TXT 模板或选择文件。
2. 设置 TXT 或 CSV 缺省字段的分类、风险、效果、优先级和来源。
3. 上传后显示解析、校验、去重和索引构建状态。
4. 展示总行数、有效数、重复数、错误数、节点数、预计常驻内存和峰值内存。
5. 错误任务可下载报告；`ready` 任务可执行候选版本试跑。
6. 管理员确认发布；发布成功后刷新规则列表和状态。

关闭弹窗不会取消任务。页面轮询活动任务；重新打开时从后端恢复状态。历史任务列表可重新查看统计和下载保留期内的报告。

### 10.4 共享 API 包

在 `packages/api` 增加精确的规则、规则集、导入、匹配和分页 DTO，以及 multipart、文件下载和任务状态客户端方法。禁止 `any`；文件响应使用 `Blob`，业务错误码保持字符串类型供冲突和阈值分支判断。

## 11. 错误处理与安全边界

- 文件类型、MIME、扩展名、大小、行数和 UTF-8 必须同时校验；不接受 ZIP，避免解压炸弹。
- CSV 使用支持引号和换行的标准解析器，禁止自行按逗号切割。
- 错误报告包含行号、字段和错误原因；原始值只存在管理员下载文件，不写日志。
- 候选索引格式、长度和校验和不匹配时拒绝加载。
- 当前有效规则集不得为空；停用操作会导致空集时拒绝候选。
- 构建超时、内存超限、对象存储失败或 MySQL 失败均保留旧版本。
- 规则发布使用单进程互斥锁；同一时刻最多一个候选进入发布。
- 管理端导出对以 `= + - @` 开头的单元格做安全转义。
- Handler 只绑定参数、读取管理员身份、调用 service 和映射统一响应。

## 12. 测试与验收

### 12.1 后端

- 分类器：关键词重叠、Unicode/繁简/全半角、allow 范围、最高风险、正则和组合规则。
- 索引：构建确定性、序列化/加载、校验和、不可变快照、旧快照并发读取和原子替换。
- 容量：规则数上限、常驻内存上限、构建峰值上限和失败后旧版本继续工作。
- Repository：版本区间、替代链、候选变更、行锁、任务恢复和发布事务回滚。
- Service：新增、修改、批量状态、重复检测、空规则集保护、版本冲突和候选试跑。
- Handler：管理员权限、分页边界、multipart 限制、模板/导出响应头及业务错误码。
- Import：CSV 引号/换行、TXT 注释、UTF-8、文件内重复、数据库重复、逐行错误和整批原子性。

Repository 使用 go-sqlmock，service 使用 gomock，handler 使用 httptest + testify。接口和 mock 变化后运行 moderation 相关测试及全量 `go test ./...`，再执行 `make swag` 并确认 Swagger 只引用 DTO。

### 12.2 前端

- `packages/api`：路径、查询参数、请求体、multipart、Blob 下载和业务错误保留。
- Hook：分页筛选、任务轮询、关闭后恢复、冲突刷新和发布后刷新。
- 组件：规则表单、批量启停、模板下载、导入各状态、错误报告和候选试跑。
- 页面：新增标签页、loading/error/empty/success、桌面与移动布局。

按前端规范为 Hook、组件和页面补齐 Vitest 测试，运行相关包测试、类型检查和 admin 构建。

### 12.3 性能基准

使用确定性生成器分别创建 10 万和 50 万条关键词，记录：

- 归一化后有效规则数及重复率。
- 节点、边和输出数量。
- 构建耗时、索引文件大小、常驻内存估算和构建峰值估算。
- 800、2000 和 10000 字符输入的无命中、少量命中和大量命中耗时。

性能测试输出报告，不用脆弱的绝对耗时作为普通单元测试断言；内存阈值和规则上限必须作为确定性测试断言。
